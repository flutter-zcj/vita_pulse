# 首页仪表盘（用例1）

## 基本流程

1. 用户打开 VitaPulse，自动进入首页仪表盘；
    1. 系统并行请求指标字典接口 `GET /vital/metric/list` 与各指标最新值接口 `GET /vital/record/latest`；
    2. 系统按指标字典的 `disp_order` 字段升序排列卡片；
2. 系统渲染今日指标卡片区；
    1. 每张卡片展示指标名称、最新值、单位、来源角标；
    2. 数值超出参考区间时，数值标红并显示越界提示；
3. 系统渲染「最近 7 次心率」迷你趋势区；
4. 用户点击「开始测量」按钮，跳转至体征测量准备页；
5. 用户点击任一指标卡片，跳转至趋势分析页并自动定位该指标；
6. 用户下拉页面，重新发起步骤 1 的请求并刷新全部数据。

## 异常情况

1. 网络异常：
    1. 请求超过 5 秒未响应，页面顶部展示提示条「网络异常」并提供「重试」按钮；
    2. 设备无网络时，卡片区展示空态插画与文案「暂无数据，请检查网络后重试」；
2. 指标字典接口返回失败：
    1. 使用 App 内置兜底的 6 项指标（心率、血氧、血压、体温、呼吸率、体重）渲染卡片；
    2. 兜底状态下不展示角标，且记录一条告警日志；
3. 单个指标无任何历史数据：
    1. 数值位置显示 `--`；
    2. 卡片右下角展示「去录入」文字入口，点击跳转手动录入页；
4. 接口返回 `code` 不等于 200：
    1. 通过 Toast 展示服务端返回的 `msg` 字段内容；
    2. 保留页面已有数据，不做清空；
5. 服务不可用（401 静默重登后仍失败）：
    1. 展示全屏提示页「服务暂不可用」与「重试」按钮。

## 业务规则

1. 卡片展示顺序完全由后端 `vital_metric.disp_order` 决定，App 不得硬编码指标顺序。
2. 指标渲染形态由 `vital_metric.disptype` 决定：`card` 为单值卡，`dual` 为双值卡（如血压 120/80），`bar` 为带进度条的卡片。
3. 记录来源为摄像头测量的显示「实时」角标，来源为手动录入的显示「手动」角标，`is_estimated = 1` 的指标显示「估算」角标。
4. 手动录入类指标（血氧、血压、体温、体重）若最近一次记录距今超过 24 小时，数值置灰并追加文案「较久未测」。
5. 参考区间取自指标字典的 `default_min` 与 `default_max`；用户自定义阈值优先于字典默认值。
6. 页面数据不做本地持久化，每次进入页面或下拉刷新均重新请求接口；同一会话内可使用内存缓存，App 进程结束后缓存失效。
7. 数值展示精度由指标字典的 `precision` 字段决定，四舍五入后展示。

## 界面描述

页面为 App 底部导航的第一个 Tab。顶部为导航栏，仅展示页面标题「今日概览」；导航栏下方为日期行；主体区为可滚动的指标卡片列表，每张卡片含指标名、数值、单位、参考区间与来源角标；列表底部为「最近 7 次心率」迷你折线卡与通栏主按钮「开始测量」；页面底部为四个 Tab 的底部导航栏。

## 编码要求

> 本章节为本页面开发实现的强制约束，生成文档时默认必须包含且必须遵守。

### 用户页面要求

1. 首屏内容渲染时间不超过 1.5 秒（4G 网络，不含首次冷启动）；
2. 数据加载期间展示骨架屏（屏占位卡片），不得出现白屏；
3. 页面**不做本地持久化存储**，不引入 Hive、GetStorage、SQLite，数据一律来自接口；
4. 指标卡片的字段与顺序由接口下发配置驱动，禁止在 Dart 代码中硬编码指标列表；
5. 下拉刷新需支持，刷新时保留原有数据不闪烁。

### 编码规范基线（默认必须遵守）

1. 遵循项目统一的 Flutter/Dart 编码规范，`flutter analyze` 须零告警；
2. 采用 GetX 模块化结构，页面由 `view / controller / binding` 三件套组成，View 层不写业务逻辑；
3. 数据接口统一通过项目封装的 `ApiClient` 调用，禁止在页面内直接发起 HTTP 请求；
4. 命名规范遵循项目约定（文件 snake_case、类名 UpperCamelCase、常量 k 前缀）；
5. 异常与边界处理遵循项目规范，统一由 `BaseController` 处理 loading 与 error 态；
6. UI 组件优先复用项目公共组件（指标卡片、骨架屏、空态页），不重复造轮子。
