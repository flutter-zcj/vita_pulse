# 体征测量进行中（用例3）

## 基本流程

1. 页面进入后立即启动相机预览并开启补光；
2. 系统按 30 帧/秒采集画面中心区域像素，计算红色通道均值，形成原始光电容积脉搏波信号；
3. 系统按每帧时间戳将信号重采样为均匀序列，执行去趋势、带通滤波、频谱分析，实时估算心率；
4. 系统在界面中央展示倒计时，从 30 秒递减至 0；
    1. 每过 1 秒刷新一次倒计时数字；
    2. 弧形进度环随剩余时间同步收缩；
5. 系统在波形卡片中实时绘制脉搏波形，并同步显示当前估算心率；
6. 倒计时归零，系统停止采集、释放相机，跳转至检测结果页，并携带本次会话的测量数据。

## 异常情况

1. 用户点击「取消检测」：
    1. 立即停止采集并释放相机；
    2. 丢弃本次全部数据，返回准备页；
    3. 不产生任何记录与接口请求；
2. 信号质量不足（信号质量分低于 0.35）：
    1. 波形卡片下方展示提示「信号较弱，请调整手指位置并保持不动」；
    2. 不中断倒计时，但结果页将标记本次数据置信度低；
3. 连续 3 秒未采集到有效帧（手指移开或遮挡）：
    1. 暂停倒计时；
    2. 展示遮罩提示「未检测到手指，请覆盖摄像头」，检测到有效帧后自动恢复；
4. 相机启动失败或被系统回收：
    1. 展示错误页「相机启动失败」与「重试」按钮；
    2. 重试仍失败则提供「改用手动录入」入口；
5. 用户在检测过程中来电或切到后台：
    1. 停止采集并释放相机；
    2. 回到前台后展示「检测已中断」提示，返回准备页；
6. 设备性能不足导致帧率低于 20 帧/秒：
    1. 判定本次测量无效；
    2. 提前结束并提示「设备性能不足，无法完成测量」。

## 业务规则

1. 测量总时长固定 30 秒，倒计时不可暂停（除手指移开导致的自动暂停）。
2. 倒计时期间不得执行页面跳转以外的其它交互，波形卡片区域不可点击。
3. 实时心率仅在采集满 15 秒后开始展示，此前显示 `--`，避免低置信度数值误导用户。
4. 本次会话产生的数据（心率、HRV、舒适度、压力等级、信号质量分、时间戳）仅保存在内存中，通过路由参数传递给结果页，不在此页落库。
5. 页面销毁（`onClose`）时必须无条件释放相机控制器，无论是否正常结束。
6. 页面须保持屏幕常亮状态，防止息屏打断测量。
7. 整个测量过程不请求任何服务端接口。

## 编码要求

> 本章节为本页面开发实现的强制约束，生成文档时默认必须包含且必须遵守。

### 用户页面要求

1. 波形刷新须达到 25 帧/秒以上，不得出现明显卡顿或跳帧；
2. 波形绘制使用 `CustomPainter` + `RepaintBoundary` 隔离重绘范围，不得触发整页重建；
3. 相机帧处理须在独立 isolate 或节流回调中完成，禁止阻塞 UI 线程；
4. 页面销毁必须释放相机，`onClose` 中执行 `dispose`，防止二次进入黑屏；
5. 页面不读写本地存储，测量数据仅存在于内存并随路由传递。

### 编码规范基线（默认必须遵守）

1. 遵循项目统一的 Flutter/Dart 编码规范，`flutter analyze` 须零告警；
2. 采用 GetX 模块化结构，页面由 `view / controller / binding` 三件套组成，View 层不写业务逻辑；
3. 数据接口统一通过项目封装的 `ApiClient` 调用，禁止在页面内直接发起 HTTP 请求；
4. 命名规范遵循项目约定（文件 snake_case、类名 UpperCamelCase、常量 k 前缀）；
5. 异常与边界处理遵循项目规范，相机与生命周期异常须有兜底路径；
6. 算法实现须下沉至 `services/ppg/` 独立模块，页面不得内联算法代码。
