# 记录列表（用例5）

## 基本流程

1. 用户从底部导航或首页入口进入记录列表页；
2. 系统调用 `GET /vital/record/list`，以 `pageNum=1`、`pageSize=20` 拉取第一页数据；
3. 系统按测量时间倒序渲染记录卡片列表；
    1. 每条卡片展示指标名称、数值与单位、来源角标、测量时间；
    2. 同一 `session_id` 的多条记录合并展示为一条会话卡片；
4. 用户点击顶部筛选栏，可按指标类型与时间范围筛选；
    1. 选择指标后重置分页并重新请求；
    2. 时间范围支持「近 7 天」「近 30 天」「全部」三档；
5. 用户上拉列表滚动至底部，系统自动加载下一页并追加渲染；
6. 用户左滑某条卡片，露出「删除」按钮，点击后调用 `DELETE /vital/record/{ids}`；
    1. 删除成功，本地移除该条并 Toast 提示「已删除」；
7. 用户点击卡片主体，跳转趋势分析页并定位到该指标、该时间点。

## 异常情况

1. 首屏请求失败：
    1. 展示空态页「加载失败」与「重试」按钮；
    2. 不清空已有列表数据（分页追加失败时）；
2. 加载下一页失败：
    1. 列表底部展示「加载失败，点击重试」；
    2. 保留已加载内容，不回滚分页游标；
3. 列表无数据：
    1. 展示空态插画与文案「暂无记录」；
    2. 提供「去录入」按钮跳转手动录入页；
4. 删除请求失败：
    1. 卡片恢复原位，撤销左滑状态；
    2. Toast 展示服务端返回的 `msg`；
5. 删除时网络断开：
    1. 提示「网络异常，删除未完成」；
    2. 不执行本地移除，保证界面与服务端一致；
6. 快速连续切换筛选条件：
    1. 以最后一次筛选条件为准，前序请求结果丢弃（请求序号校验）；
7. 一页数据为空但总数不为零（越界翻页）：
    1. 停止继续加载，底部展示「没有更多了」。

## 业务规则

1. 列表按 `measured_at` 倒序排列，同一会话的多条指标记录聚合为一条卡片展示。
2. 分页每页 20 条，滚动到距底部 200dp 时触发下一页加载，加载中不重复触发。
3. 筛选条件变更时须重置 `pageNum` 为 1，并清空当前列表后重新渲染。
4. 删除为物理删除（服务端按 `del_flag` 逻辑删除），删除后不提供撤销。
5. 卡片来源角标规则与首页一致：`camera` 显示「实时」，`manual` 显示「手动」，`is_estimated=1` 追加「估算」。
6. 测量时间展示规则：当天显示「今天 HH:mm」，昨天显示「昨天 HH:mm」，更早显示「MM-dd HH:mm」，跨年显示「yyyy-MM-dd」。
7. 页面数据不做本地持久化，每次进入页面重新拉取第一页；不做离线缓存。

## 界面描述

顶部为导航栏，左侧返回按钮，中间标题「测量记录」。导航栏下方为筛选栏，含指标下拉与时间范围分段控件。主体为可滚动的记录卡片列表，每张卡片采用「信息列表卡片」结构：标题行含指标名称与来源状态标签，中部为数值与单位，下部为测量时间，右侧为跳转箭头。列表底部展示加载状态文案。页面右下角无悬浮按钮，新增入口位于首页与空态页。

## 编码要求

> 本章节为本页面开发实现的强制约束，生成文档时默认必须包含且必须遵守。

### 用户页面要求

1. 列表滚动须保持 60 帧流畅，卡片使用 `ListView.builder` 按需构建；
2. 分页加载须做请求序号校验，避免快速切换筛选导致旧响应覆盖新数据；
3. 左滑删除使用项目统一的手势组件，滑动阈值不小于屏宽 30%；
4. 页面**不做本地持久化**，不引入本地数据库；进入页面与切换筛选均请求接口；
5. 卡片日期格式统一走项目 `DateFormatUtil`，禁止页面内自行拼接字符串。

### 编码规范基线（默认必须遵守）

1. 遵循项目统一的 Flutter/Dart 编码规范，`flutter analyze` 须零告警；
2. 采用 GetX 模块化结构，页面由 `view / controller / binding` 三件套组成，View 层不写业务逻辑；
3. 数据接口统一通过项目封装的 `ApiClient` 调用，禁止在页面内直接发起 HTTP 请求；
4. 命名规范遵循项目约定（文件 snake_case、类名 UpperCamelCase、常量 k 前缀）；
5. 异常与边界处理遵循项目规范，分页与删除失败须有明确的状态回退；
6. UI 组件优先复用项目公共组件（列表卡片、空态页、加载更多），不重复造轮子。
