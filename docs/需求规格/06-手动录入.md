# 手动录入（用例6）

## 基本流程

1. 用户从首页「去录入」入口或记录列表空态页进入手动录入页；
2. 系统加载指标字典，渲染指标类型下拉框，默认选中「血氧」；
3. 用户选择指标类型，系统联动更新数值输入区；
    1. 选择血氧、体温、体重、心率、呼吸率时，展示单个数值输入框与只读单位；
    2. 选择血压时，展示收缩压与舒张压两个数值输入框，单位为 `mmHg`；
4. 用户输入数值，系统实时执行范围校验并给出提示；
5. 用户选择测量时间，默认值为当前时间，可向前调整；
6. 用户填写备注（选填，最多 140 字）；
7. 用户点击「保存」按钮，系统调用 `POST /vital/record` 提交；
    1. 保存成功后 Toast 提示「已保存」，返回上一页；
    2. 上层页面重新拉取数据并刷新展示。

## 异常情况

1. 必填项为空（指标类型或数值）：
    1. 「保存」按钮保持禁用状态；
    2. 对应输入框下方展示「请输入数值」；
2. 数值超出合法范围：
    1. 输入框标红，下方展示具体范围提示（如「血氧范围 70–100」）；
    2. 阻止提交；
3. 数值格式非法（非数字、多个小数点、负数）：
    1. 输入时即过滤非法字符；
    2. 失焦后展示「请输入有效数字」；
4. 血压只填了收缩压或只填了舒张压：
    1. 提示「收缩压与舒张压需同时填写」；
    2. 阻止提交；
5. 测量时间选择晚于当前时间：
    1. 提示「测量时间不能晚于当前时间」；
    2. 时间控件自动回退到当前时间；
6. 提交请求失败：
    1. Toast 展示服务端返回的 `msg`；
    2. 保留全部已填内容，按钮恢复可点击，允许重试；
7. 用户未保存直接返回：
    1. 若已修改任意字段，弹出二次确认「内容未保存，确定离开？」；
    2. 未修改则直接返回。

## 业务规则

1. 手动录入的 `source` 字段固定为 `manual`，`quality` 字段为空。
2. 各指标的合法范围：心率 30–220 bpm；血氧 70–100 %；体温 34.0–42.0 ℃；体重 20–300 kg；呼吸率 5–60 次/分；收缩压 60–260 mmHg；舒张压 30–180 mmHg。
3. 血压需同时写入两条记录（`systolic` 与 `diastolic`），两条记录共享同一 `session_id`。
4. 数值精度：体温保留 1 位小数，体重保留 1 位小数，其余指标为整数。
5. 测量时间默认当前时间，允许向前调整，最早不早于 2000-01-01。
6. 备注字段为选填，最长 140 字，超长时截断并提示。
7. 保存成功后不做本地持久化，由上层页面重新请求接口获取最新数据。

## 界面描述

顶部为导航栏，左侧返回按钮，中间标题「手动录入」。主体为竖向表单，自上而下依次为：指标类型下拉框（必填）、数值输入框（必填，随指标类型联动切换单值或双值）、只读单位展示、测量时间选择器（必填）、备注多行输入框（选填，带字数计数）。底部为固定操作区，通栏主按钮「保存」。

## 编码要求

> 本章节为本页面开发实现的强制约束，生成文档时默认必须包含且必须遵守。

### 用户页面要求

1. 指标类型切换时须在 100 毫秒内完成数值输入区联动更新，且清空已输入的数值；
2. 数值输入框须限制键盘类型为数字键盘，体温与体重允许小数点；
3. 表单校验须在前端完成，校验通过后方可提交，不得依赖服务端兜底；
4. 保存过程须展示 loading 状态并禁用按钮，防止重复提交；
5. 页面**不做本地持久化**，草稿不落盘；未保存退出须二次确认。

### 编码规范基线（默认必须遵守）

1. 遵循项目统一的 Flutter/Dart 编码规范，`flutter analyze` 须零告警；
2. 采用 GetX 模块化结构，页面由 `view / controller / binding` 三件套组成，View 层不写业务逻辑；
3. 数据接口统一通过项目封装的 `ApiClient` 调用，禁止在页面内直接发起 HTTP 请求；
4. 命名规范遵循项目约定（文件 snake_case、类名 UpperCamelCase、常量 k 前缀）；
5. 异常与边界处理遵循项目规范，输入校验须覆盖空值、越界、格式非法三类场景；
6. UI 组件优先复用项目公共组件（表单行、时间选择器、数字输入框），不重复造轮子。
