# 预警阈值设置（用例8）

## 基本流程

1. 用户从设置页进入预警阈值设置页；
2. 系统并行请求指标字典与用户阈值规则 `GET /vital/alertRule`；
3. 系统按指标顺序渲染阈值配置列表；
    1. 每条展示指标名称、当前下限、当前上限、启用开关；
    2. 未配置过的指标展示字典默认区间；
4. 用户点击某条配置，页面底部弹出阈值编辑面板；
    1. 面板内含下限输入框、上限输入框与「恢复默认」按钮；
    2. 输入过程实时校验下限必须小于上限；
5. 用户点击面板内「确定」，系统调用 `PUT /vital/alertRule` 保存该条规则；
    1. 保存成功后面板收起，列表项即时更新；
6. 用户切换某条规则的启用开关，系统调用同一接口更新 `enabled` 字段；
7. 用户点击「恢复默认」，面板内数值回填为该指标的字典默认区间，点击「确定」后生效。

## 异常情况

1. 阈值规则请求失败：
    1. 列表展示「加载失败」与「重试」按钮；
    2. 提供「使用默认区间」按钮，本地渲染字典默认值（不可编辑，仅查看）；
2. 下限大于等于上限：
    1. 对应输入框标红，提示「下限必须小于上限」；
    2. 「确定」按钮禁用；
3. 阈值超出指标物理范围（如心率上限填 400）：
    1. 提示「阈值超出合理范围」；
    2. 阻止提交；
4. 保存失败：
    1. 面板保持展开状态，保留已填数值；
    2. Toast 展示服务端返回的 `msg`；
5. 开关切换请求失败：
    1. 开关回滚到原状态；
    2. Toast 提示「设置未生效，请重试」；
6. 快速连续切换同一开关：
    1. 以最后一次状态为准，前序请求结果丢弃；
    2. 切换过程中开关进入不可点击状态。

## 业务规则

1. 阈值规则的合法区间必须落在指标字典的物理范围内（以 `vital_metric.default_min/default_max` 为外边界）。
2. 下限必须严格小于上限，二者不允许相等。
3. 未配置规则的指标默认继承字典区间，`enabled` 默认为开启。
4. 规则保存后立即生效，服务端在下一次体征数据写入时据此判定是否生成预警事件。
5. 血压类指标按收缩压、舒张压分别配置规则，不合并为一条。
6. 关闭某条规则的开关后，该指标不再产生新的预警事件，历史事件保留。
7. 页面数据不做本地持久化，每次进入页面均重新请求规则；保存后以服务端返回结果为准刷新列表。

## 界面描述

顶部为导航栏，左侧返回按钮，中间标题「预警阈值」。主体为竖向配置列表，每行为一张卡片，含指标名称、当前区间文本（如「60 – 100 bpm」）、右侧启用开关与进入编辑的箭头。底部无固定按钮，编辑通过底部弹出面板完成，面板内含上下限输入框与「恢复默认」「确定」按钮。

## 编码要求

> 本章节为本页面开发实现的强制约束，生成文档时默认必须包含且必须遵守。

### 用户页面要求

1. 阈值编辑使用底部弹层（`Get.bottomSheet`）实现，弹层高度不超过屏幕 50%；
2. 开关切换须做乐观更新 + 失败回滚，回滚过程不得闪烁；
3. 输入校验须在前端完成，校验不通过时禁止调用保存接口；
4. 页面**不做本地持久化**，规则数据一律来自接口，保存后以服务端返回为准。

### 编码规范基线（默认必须遵守）

1. 遵循项目统一的 Flutter/Dart 编码规范，`flutter analyze` 须零告警；
2. 采用 GetX 模块化结构，页面由 `view / controller / binding` 三件套组成，View 层不写业务逻辑；
3. 数据接口统一通过项目封装的 `ApiClient` 调用，禁止在页面内直接发起 HTTP 请求；
4. 命名规范遵循项目约定（文件 snake_case、类名 UpperCamelCase、常量 k 前缀）；
5. 异常与边界处理遵循项目规范，开关回滚与保存失败须有明确反馈；
6. UI 组件优先复用项目公共组件（设置项卡片、底部弹层、开关行），不重复造轮子。
