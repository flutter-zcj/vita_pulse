# 系统设置（用例9）

## 基本流程

1. 用户点击底部导航「设置」进入本页；
2. 系统展示设置项分组：
    1. 数据分组：预警阈值、测量提醒；
    2. 显示分组：外观模式（跟随系统 / 浅色 / 深色）；
    3. 服务分组：服务器地址、连接测试；
    4. 关于分组：隐私政策、免责声明、版本号；
3. 用户点击「预警阈值」，跳转阈值设置页；
4. 用户切换外观模式，界面即时切换并持久保存该偏好（用户偏好，非业务数据）；
5. 用户点击「服务器地址」，弹出输入面板，可修改后端服务地址；
    1. 点击「测试连接」，系统请求 `/health` 校验可达性；
    2. 连接成功提示「连接正常」，失败提示具体错误；
6. 用户点击「免责声明」，弹出全屏说明页，展示健康数据使用边界；
7. 用户点击「版本号」所在行，连续点击 5 次显示调试信息（构建时间、接口地址、令牌状态）。

## 异常情况

1. 服务器地址格式非法：
    1. 输入框标红，提示「请输入合法的 http/https 地址」；
    2. 「测试连接」与「保存」按钮禁用；
2. 连接测试超时（5 秒）：
    1. 提示「连接超时，请检查地址与网络」；
    2. 保留已填地址，允许修改后重试；
3. 修改服务器地址后连接失败：
    1. 提示「新地址不可用，已保留原地址」；
    2. 不覆盖原有可用配置；
4. 外观模式切换异常：
    1. 回滚到切换前模式；
    2. Toast 提示「切换失败，请重试」；
5. 免责声明内容加载失败：
    1. 使用内置静态文案兜底展示；
    2. 不展示空白页面；
6. 版本信息读取失败：
    1. 版本号展示 `--`；
    2. 不阻塞其它设置项。

## 业务规则

1. 本页仅「外观模式」与「服务器地址」属于用户偏好配置，允许本地持久化；业务数据一律不落本地。
2. 服务器地址变更后须清空当前登录令牌并重新静默登录，避免旧令牌指向旧服务。
3. 连接测试使用 `GET /health` 接口，超时时间固定 5 秒。
4. 免责声明文案须完整表达：本产品为健康参考工具，非医疗器械，测量结果不能用于诊断或治疗决策。
5. 版本号读取自 `pubspec.yaml` 的 `version` 字段，展示格式为 `v1.0.0 (build 1)`。
6. 本页不提供「清空本地数据」入口，因为业务数据不在本地存储。
7. 调试信息仅在连续点击版本号 5 次后展示，正式环境不默认暴露。

## 编码要求

> 本章节为本页面开发实现的强制约束，生成文档时默认必须包含且必须遵守。

### 用户页面要求

1. 设置项点击响应须在 100 毫秒内给出视觉反馈（水波纹）；
2. 外观模式切换须即时生效，不得重启 App；
3. 服务器地址修改后须清空令牌并触发静默登录，此逻辑由 `AuthService` 统一处理；
4. 本页仅允许持久化「外观模式」与「服务器地址」两项偏好，**业务数据禁止本地存储**；
5. 免责声明页使用项目统一的全屏文本页组件，支持返回与滚动。

### 编码规范基线（默认必须遵守）

1. 遵循项目统一的 Flutter/Dart 编码规范，`flutter analyze` 须零告警；
2. 采用 GetX 模块化结构，页面由 `view / controller / binding` 三件套组成，View 层不写业务逻辑；
3. 数据接口统一通过项目封装的 `ApiClient` 调用，禁止在页面内直接发起 HTTP 请求；
4. 命名规范遵循项目约定（文件 snake_case、类名 UpperCamelCase、常量 k 前缀）；
5. 异常与边界处理遵循项目规范，配置类操作须有成功与失败的双向反馈；
6. UI 组件优先复用项目公共组件（设置行、分组标题、弹层输入框），不重复造轮子。
